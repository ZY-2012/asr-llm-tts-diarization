# 实时会议链路：模块输出格式、时间线与延迟极限分析

> 分支 `diart-incremental`，2026-10-14。数据来自板端 2P 60s 截断 file-realtime 实测
> （`config-2pw-inc-preview3.yaml`：`max_segment_seconds=10`、`preview_seconds=3`、
> session chunk=step=10、增量聚类）。暂不涉及 LLM / TTS。

## 1. 架构与数据流

```
麦克风/文件 16kHz PCM
   │
   ├──► FastEnhance 降噪(48kHz) ──► 降采样16k ──► TEN-VAD(每16ms 有声/静音)
   │                                                   │ voiced hops
   │                                                   ▼
   │                                          Accumulator 分段器
   │                                     ┌──── 预览段(累计3s语音, 每段一次)
   │                                     └──── 正式段(1s静音结束 或 满10s)
   │                                                   │
   │                                                   ▼
   └──► diar_decimator ──► SessionDiarizer ──► 说话人时间线 ──► ResultWorker 编排器
        (原始音频, 不经降噪)   每满10s送一个窗                  │ 预览段: 直接整段ASR
                              给 diar-worker 子进程            │ 正式段: 等时间线覆盖段尾
                              (分割+embedding+增量聚类)        │        → 按说话人切片 → ASR
                                                               ▼
                                              SenseVoice ASR (NPU2)
                                                 │                 │
                                transcript_streaming.txt     transcript.txt
                                 pending@时间 文本            speaker-N@时间 文本
```

两条并行支路：①降噪→VAD→分段→ASR；②说话人分离。二者在 ResultWorker 汇合：
正式段必须等说话人时间线覆盖到段尾，才能切片送 ASR。

## 2. 时间线（会议开始 t=0，音频时间轴）

| 时刻 | 模块 | 事件 | 日志/输出 |
|---|---|---|---|
| 每16ms | TEN-VAD | 判有声/静音 | 内部 bool，不外吐 |
| ~3.0s | Accumulator | 预览段 | `[vad] preview submitted duration=3.008s` |
| ~3.3s | ASR | 预览转写（无说话人） | `pending@… 哎，小哥听得到不可以听到啊，是这样。` |
| ~10.0s | Accumulator | 首个正式段（满10s） | `[vad] segment submitted duration=10s` |
| ~10.2s | 说话人分离 | 首个窗提交 | `session window start=0s … parts=3 committed=10s wall=+10.2238s` |
| ~10.5s | ASR | 按说话人切片转写 | `speaker-1@… 哎，小崔听得到不？` / `speaker-2@… 可以听到。` |
| 每10s | 说话人分离 | 下一个窗提交 | `wall=+20.21s / +30.21s / …`，单窗推理 ~0.23s |
| 不定 | Accumulator | 1s静音提前结束或满10s | 每段一次预览 + 一次正式 |

## 3. 各模块输出格式

| 模块 | 输出 | 格式示例 |
|---|---|---|
| TEN-VAD | 每 16ms 一个 voiced bool（内部） | — |
| Accumulator | `Segment`：去静音拼接 PCM `samples`、`runs`（拼接偏移↔源偏移）、保留静音的 `raw_samples`、`is_preview`、`wall_start/end` | 段 WAV `20261014-10-44-45-380_20261014-10-44-53-252.wav` |
| 说话人分离（每窗） | 窗内说话人片段 + 聚类日志 | `[diar] wav=session-0.wav audio=10.00s clusters=2 parts=3 took=242ms`；`created new speaker-1` / `matched speaker-1 cosine=0.953` |
| 说话人分离（每段） | `<段>.wav.parts.txt`，单位 16k 采样点 | `3` / `0 23040 speaker-1` / `23040 34048 speaker-2` / `34048 160000 speaker-1` |
| 说话人档案 | `speakers.json` | `{"speaker_id":"speaker-1","sample_count":537198,"last_seen_time":…,"embedding_center":[256 维]}` |

## 4. 为什么「说话人+文字」现在是 ~10.5s

说话人+文字 = 说话人时间线覆盖了这段话的段尾 + 这段的 ASR。下面三个因素叠加：

1. **分割模型窗长固定 10s。** community-1 的分割模型输入固定 `WINDOW_SAMPLES`=10s（输出 589 帧）。
   首个窗必须攒满 10s 真实音频，所以冷启动首标签 ≥10s。
   试过 `session_first_window_sec=5`（不足部分补零）：首标签提前到 5.2s，但后续窗无法匹配首窗的质心，
   60s 里多出 speaker-3/4 两个幻影说话人。分割前的均值/方差归一化覆盖整窗（含补零区），
   embedding 也算在补零的整窗 fbank 上，这两点是推测的原因，还没逐项验证。
2. **提交步长 = 10s，窗与窗不重叠。** 时间线只在 10s、20s、30s… 推进。这一点影响**稳态**，不只冷启动：
   一句在 t=11s 结束的话要等 t≈20.2s 那个窗提交后才有说话人，等待 0–10s，平均约 5s。
   之前说的「稳态标签延迟 ~0.2s」只是窗尾到提交的推理时间，不是每句话的延迟。
3. **ResultWorker 等整段被覆盖。** 正式段要等时间线覆盖到段尾（段最长 10s）才开始切片和 ASR，
   段内靠前的话也要跟着等。

所以 10.5s 是冷启动的值；稳态下每句话「说完 → 有说话人+文字」大约是 0–10s 的等待 + ~0.3s ASR，不是固定 0.2s。
单窗推理只有 ~0.23s（NPU，RTF 0.023），**算力不是瓶颈，窗长和步长才是**。

## 5. diart「~1s 出结果」：哪些是真的，哪些有前提

源码：`diart/src/diart/operators.py`、`blocks/aggregation.py`、`blocks/base.py`、`utils.py`。

**真的部分：** 5s 滚动窗、0.5s 步长、每步算量恒定；`DelayedAggregation` 每步只输出
`[buffer_end - latency, buffer_end - latency + step]` 这一小段，所以**稳态**下每 0.5s 的音频在约 latency（0.5–5s）后拿到说话人。
这正是我们缺的：步长短、窗重叠。

**有前提、宣传里不显眼的部分：**

| 点 | 源码依据 | 实际含义 |
|---|---|---|
| latency 是稳态算法延迟，不是首标签时间 | `rearrange_audio_stream` 里 `ops.filter(has_samples(chunk_samples))`：chunk 不满 5s 不输出 | 麦克风冷启动要等满 5s 才有第一个标签 |
| 文件评测把冷启动藏掉了 | `get_file_padding` → `get_padding_left`：流比 chunk 短时在左侧补零 | benchmark 的 DER/延迟不反映麦克风冷启动 |
| 首个 buffer 特殊处理 | `aggregation.py` `_prepend` 带 `FIXME`：首 buffer 直接把 `[0, end]` 整段输出 | 开头一段是一次性给出的，不是逐 0.5s |
| latency 不含计算时间 | README 的 11ms/26ms 是 Ryzen 9 / RTX 4060 上单独测的；`Benchmark` 预先批量算模型输出 | 慢设备上实际延迟 = latency + 推理 |
| 低延迟换精度 | README Figure 5 / 论文：延迟从 5s 降到 0.5s，DER 上升 | 0.5s 可用，但不是 5s 的精度 |
| 只有说话人，没有文字 | diart 不含 ASR | 说话人+文字还要等 ASR 有足够上下文；0.5s 片段 ASR 质量差 |
| 模型不同 | 默认 `pyannote/segmentation`（2021，5s 窗） | 我们用 community-1（10s 窗），不能直接套 5s |

结论：「~1s」指**稳态**下说话人标签的算法延迟，这部分不夸张，也是我们可以借鉴的。
但它不是「开口 1s 出说话人+文字」：麦克风冷启动 ≥5s，计算时间另算，文字也不在里面。

## 6. 还能怎么提速（按收益/风险排序）

| 方案 | 预期 | 风险/代价 |
|---|---|---|
| A. **滚动窗：窗 10s、步长 2s（已实测，2026-10-14）** | 稳态说话人延迟从平均 ~5s（最坏 10s）降到 ~2s + 推理 | 推理占空比 ~12%（0.24s/2s）；重叠窗下增量质心重复计数与 diart 同构（diart 每步也把整窗 embedding 累加进质心），2P 60s 实测恰好 2 人、无幻影；`session_step_sec` 基础设施 P1b 已备好，纯配置 |
| B. **ResultWorker 按片提交（已实现，见 §7）** | 段内靠前的说话人片一被覆盖就切片送 ASR，不等段尾 | 已与 A 叠加实测 |
| C. 预览段临时说话人 | 说话人档案建立后（>10s），预览音频只和已有质心比对、不新建说话人，~3s 出「临时说话人+文字」，正式结果再修正 | 3s 短音频 embedding 偏弱，需验证正确率 |
| D. 冷启动 <10s | 补零改为只用有效样本做归一化，或用反射填充 | 实验性；m5f5 已证明朴素补零不可行 |

目标已基本达成（A+B，2P 60s 板端实测）：冷启动 10.2s 不变（10s 模型窗 +
0.24s 推理），首条说话人+文字 11.1s；**之后每句「说完到有说话人+文字」
10.5–20.5s → 2.5–2.9s**（段尾 1s 静音判定 + 2s 步长 + 0.24s 推理 + ~0.3s
ASR）。文本、说话人归属、段边界与 step=10 逐字一致，无幻影说话人。

## 6b. 段粒度（2026-10-14）：max_segment 10→5，输出从「一阵一阵」变「流水」

**问题**：A+B 之后每句说完 → 出结果只要 2.5s，但**下一句要等 10s+**。用户
观感：说话人时间轴只落后 ~2.2s，可「说话人+文字」是 12–16s 一大串地蹦。
根因不在 diar，在 VAD 段粒度：连续独白攒满 `max_segment_seconds=10` 有声
才成段，整段一起出文字，段中间的话要陪段尾等 10s+。

**修法**：`vad.max_segment_seconds` 10→5（纯配置，diar 走独立的原始音频流
不受分段影响，2P 60s 实测无幻影、说话人归属一致）。

| 指标（60s 实测，step=2） | 段长 10s | 段长 5s |
|---|---|---|
| 说话人+文字输出间隔 | 12–16s 一大串 | **2–8s 一小段** |
| 每段说完 → 出文字 | 2.5–2.9s | **1–2.3s** |
| 预览文字频率 | 每 10s+ | 每 ~6s |

**代价**：流利独白被硬切在 5s 处，切点可能落在词中间，两侧各糊/丢几个字
（实测一处：「把直接全部人就不就不租了」→「把这些全部人都不就不足了」）。

**`vad.pause_split_seconds`（已实现，默认 0=关）**：段内攒够该秒数有声后，
遇到 ≥0.2s 自然停顿就成段（而非等 1s 尾静音或硬上限），让切点落在停顿上。
停顿阈值 2026-10-14 从 0.3s 降到 **0.2s**：实测本 2P 素材段内真停顿（词间）
为 144–720ms、而词内 VAD 抖动 <100ms，0.2s 恰好落在两者之间——4–5s 高发
硬切区内存在 208/224ms 停顿（原 0.3s 阈值全错过）。降阈值后 pause_split
在本素材即可命中，硬切糊字预期减少；不命中则退化为硬切，无副作用。

## 6c. 快字流水（2026-10-14）：预览从每段一条改为链式切片

**问题**：预览原来每段只发第一条（前 `preview_seconds` 秒有声），长独白中后
段没有快速文字，要等说话人+正式文字。

**改动**（`framework/audio_pipeline.cpp`，`Accumulator::EmitPreview`）：
预览改为链式——每攒够 `preview_seconds` **新增**有声就再发一片，片间用
`runs` 映射回源时间轴，ASR 输入带 0.2s 回够防词头被切；格式统一为
`pending@[起,止] 文字`（events.jsonl 的 preview 事件同样带 b/e）。

**结果**（60s，preview=2s，step=2，段长 5s）：首条快字 2.78s（2.64s 有声 +
0.14s ASR）；每片说完到出字 0.14–0.6s；60s 共 19 条，说话期间文字基本不断。
演示页「快字间隔」可选 1/2/3s 或关；正式说话人+文字出来后以其为准。

**词安全切点（2026-10-14）**：链式切片原为盲切——攒够间隔就切，切点落在词
中间就会糊字（「你觉得哪种方式」→「你的拿种方式」），反馈「错字漏字变多」
即源于此。现改为**停顿优先切**：切点落在 ≥0.2s 的词间停顿上（词内 VAD 抖动
<150ms、词间真停顿 ≥190ms，0.2s 恰在中间），完全无停顿的流利段才盲切兜底
（阈值放宽到 2× 间隔）。段级 `pause_split` 同步把停顿阈值降到 0.2s，让 4–5s
处的成段也落在词间停顿而非硬切。

**停顿优先的三条规则（v4 实现要点，`Accumulator` unvoiced 分支）**：
1. **段内链式切**：攒够 `preview_seconds` 新增有声后，遇 ≥0.2s 停顿立即切；
2. **关段同切尾片**：关闭段的那次停顿（trailing / pause_split）顺带把未预览
   的尾巴也切出来——快字比 final 早 0.2–1.3s 落地，说话人标签随后顶上。
   没有这条时 pause_split（≥4s）会饿死链式切片：够切片间隔的停顿必然已
   先关掉了段；
3. **首片半间隔门槛**：未预览有声 ≥ `preview_seconds/2` 即可停顿切。实测
   停顿集中在段内 1.2–2.2s 有声处——首片常比固定 2s 盲切**更早**且词安全
   （v4：首条快字 2.78s→**1.56s**，切在 1.23s 处的 496ms 真停顿上）。

**v4 结果**（60s，preview=2，step=1，trail=0.5，maxseg=5，psplit=4）：
16 条快字，说完→出字 0.13–0.50s；13 条落在停顿上（尾片全部完整：「方案
比较好吧。对，因为现在。」「且许多员工也不好找房子。」）。残留 3 处盲切
（「公司下」「风案」「这个房」）均在 5s 内无任何 ≥200ms 停顿的满流利段，
属设计内兜底。正式 finals 的段边界全部落在停顿上；仅 3 个满流利段打满 5s
硬上限（其糊字为 SenseVoice 对连续独白的固有噪声，与切点无关）。

**再压一档（step=1 + 句尾静音 0.5s，60s 实测）**：稳态每片说完→出
「说话人+文字」**0.36–1.45s**（step=2+trail=1 时为 1.5–2.3s），文字质量与
step=2 逐字一致。两句之间的输出间隔 3–6s，由实际语音的停顿结构决定
（独白按 4–5s 成段），不再是管线等待。注意 trail=0.5 会移动 VAD 段边界
（b/e 时间戳随之变化），DER 评测基线仍用 trail=1。

**关于「去掉 VAD 会不会更实时」**：不会。diar 吃的是每帧原始音频流
（`SessionDiarizer::Append` 不分有声/静音），提交节奏只由窗口/步长决定，
与 VAD 无关。VAD 只影响 ASR 的分段；去掉它 ASR 只能盲切（静音也进上下文、
无句边界），文字质量会明显变差。现状（VAD 管 ASR 分段、独立流管 diar）
就是解耦的。

## 7. Plan B 已实现（2026-10-14）：段内逐片释放

**问题**：首条「说话人+文字」实测 20.3s，不是预期的 10.5s。根因是 VAD 段与
diar 提交窗错位：首个 VAD 段攒满 10s 有声后于 t≈10.9s 提交，其源时间轴终点
（静音被剔除）延伸到 10.94s；而首窗 diar 只覆盖到 10.0s，必须等第二窗 20.2s
提交。段内所有内容（包括 0–2s 的开头两句）都被段尾拖住。

**改动**（`framework/audio_pipeline.cpp`）：
- `SessionDiarizer` 新增 `Committed()`/`Finished()`；`ConcatCoveredBySource()`
  将 diar 覆盖前沿（源采样点）映射回拼接坐标。
- `ResultWorker::StreamSessionParts()`：不再等整段被覆盖，而是每当 diar 提交
  一次，就把「已覆盖前缀内、且距覆盖前沿 ≥0.3s（kMinPartSamples，防后续
  re-merge/absorb 改变切分）」的完整片段立刻切片送 ASR，写 transcript、发事件。
- 片段转写抽成 `TranscribePart()`，预览与正式路径共用。

**结果**（2P 60s，events.jsonl 实测）：

| 指标 | 改前 | 改后 |
|---|---|---|
| 首条说话人+文字 | 20.35s | **11.07s** |
| 说话人+文字平均延迟 | 9.4s | 7.0s |

文本与说话人归属逐字一致（无精度变化）。剩余延迟来自跨提交边界的段尾，
需 Plan A（滚动窗 step 1–2s）继续压。

**首字时间澄清**：预览首字 = preview_seconds 的**有声**样本攒满时刻 + ASR
（~0.2s）。2P 开头含 ~0.9s 静音，故 4.1s 而非 3.3s；连续说话时 ~3.3s。
冷启动「说话人+文字」下限 = 10s 模型窗 + 首片 ASR ≈ **11s**。

**单面板「先流式后对账」（P4，2026-10-15）**：转写区只有一个 feed——

- 行先以**实时流式**出现：黑色已确认 + 灰色暂定尾（LA-2），时间戳
  `[start–end]` 随节拍加宽；说话人标签按纪元区间与 diar 时间线重叠贴色，
  纪元跨说话人换人时显示**两个说话人标签**（0.2s 纪元停顿阈值低于说话人
  换话间隙时会吞掉换人点，P3 单标签取占比最大者会错贴——如 60s 开头
  speaker-2 的「可以听到」被贴成 speaker-1）。
- finals 到达后**原地对账**：每条 final 唯一归属重叠最大的行（echo-free，
  绝不跨行重复），归属行在其原位展开为**每 final 一行**的权威稿
  （`说话人 [b–e] 文字`，行级滞后不显示、延迟看顶部统计栏）——跨说话人纪元
  自然拆成多行分色（上例对账后即 speaker-2「可以听到。」独立一行 +
  speaker-1 后续各一行）。33min 实测：482 finals 中 481 条唯一归属、
  仅 1 条独立插入；170/173 条未获归属的行因区间已被别行 finals 完整
  覆盖而移除（防灰字重复）；43 行跨说话人拆行，行文案 p50=16 / max=78 字。
- 无纪元覆盖的 final（稀疏语音，纪元按设计丢弃）按时间序插入独立权威行；
  tick=0 旧快字模式同面板兼容：快字行被覆盖 final 吸收。

「模拟流式」开关把打字行逐字显示（纯前端效果，不影响流式/对账逻辑）。

## 9. 固定节拍流式文本链（streaming-slicer，2026-10-14）

**问题**：v4 快字链（§6c）的输出节奏仍由**停顿**门控——满流利独白中 ≥0.2s
的停顿可能 4–5s 才出现一次，期间快字完全断流（60s 实测最大空档 4.9s）。

**架构（P0 数据定案，板上 asr-probe 实测）**：放弃 ASR 库的流式接口
（`AX_ASR_StreamFeed` 对非流式 sensevoice.axmodel 产生乱值 partial 且累计
~3s 段错误），改用**纪元锚定增长窗 + 整窗重转写**：

- **纪元（epoch）**= 被 ≥0.2s 停顿隔开的语音串（词安全切点，§6c 已验证）。
  纪元内窗口**左端固定**（纪元起点）、右端随音频增长——左端不动，永无啃词。
- **节拍（tick）**：纪元内每 `stream_tick_seconds` 秒把整个纪元窗送
  `AX_ASR_RunPCM` 内存直转（实测 ~21ms/s，3s 窗 ~150ms，12s 窗 ~280ms，
  0.8s 节拍预算充裕），完全不依赖词级时间戳。
- **合并（LA-2，标点宽松）**：连续两拍假设的**最长公共前缀**（跳过标点比对
  ——SenseVoice 对 `吧？→吧→吧？` 的标点抖动会卡死逐字节前缀）为已确认
  文字（黑色实心），其余先以灰色暂定尾显示，下一拍确认。**长度优先修订**：
  更长的连续一致前缀可修订早先提交的单字抖动（如不稳定的人名 陈/飞/崔）。
- **定稿（sfinal）**：纪元结束（停顿确认 / 12s 硬上限 / 流结束）提交整纪元
  假设——这是该纪元质量最高的视图。12s 硬上限仅对连续无停顿的极端独白
  生效（v4 残留 3 处盲切即属此类场景，由纪元重锚 + LA 覆盖）。

**并发与 NPU**：StreamSlicer 独立线程，与 diar/finals 共用 SenseVoice 句柄，
ASR 前后走 NPU2 仲裁（与旧 preview 路径同模式）；队列 256 hop（~4s）drop-oldest
防 VAD 回压。60s 实测 NPU 占用：fastenhance 4.7% + ten-vad 2.3%，ASR tick
~0.15–0.28s/0.8s，与 diar 共存无竞争恶化。

**finals 零改动**：流式文本仅作实时观感；transcript/MP3/RTTM/DER 继续走
现有 VAD 段 + diar finals，质量与 v4 逐字一致（60s 实测 15 条 finals、
首条 10.37s，与基线相同）。

**事件**（events.jsonl，demo 页流式面板）：
- `stext {b,e,add,text,tail}`：节拍增量；`text`=纪元已确认全文（黑色），
  `tail`=灰色暂定尾，`add`=新增确认字（信息性）；
- `sfinal {b,e,text}`：纪元定稿，整行替换；说话人标签随后贴（页面按
  纪元区间与 diar 时间线重叠贴色，跨说话人纪元双标签——P3+P4）；
- `final {b,e,spk,text}` 到达后页面原地对账（§8 单面板规则）。

**结果**（2P 60s，tick=0.8s，step=1，trail=0.5，maxseg=5，psplit=4，preview=0）：

| 指标 | v4 快字链 | streaming-slicer |
|---|---|---|
| 首个快字 | 1.56s | **0.94s** |
| 稳态出字节拍 | 停顿门控，空档可达 4.9s | **固定 0.82s** |
| 句尾定稿（sfinal − 句尾） | — | 0.2–0.5s |
| 首个说话人+文字 | 10.4s | 10.4s（不变） |

**配置**：`vad.stream_tick_seconds`（0=关，默认关）、`vad.stream_pause_seconds`
（0.2s）、`vad.stream_epoch_max_seconds`（12s）。演示页「流式文字」下拉即
`tick` 参数；开流式时服务端强制 `preview=0`（双通道会出重复快字）。

**已知残留**：灰色尾在 ASR 修订早先文字（人名抖动）时短暂重复已显示内容，
下一拍自愈，sfinal 定稿；SenseVoice 人名不稳定（陈/崔/飞）为模型固有噪声，
finals 路径同样存在。
